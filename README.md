# 投资数据看板（PID）

一个**自动更新、可视化**的个人投资数据看板。每天从公开数据源抓取商品、指数的价格与估值数据，存入数据库、导出为静态 JSON，并通过一个纯前端页面（GitHub Pages）呈现。

**在线地址**：https://gmbob990132.github.io/PID/

---

## 这个项目是做什么的

跟踪投资决策所需的**关键数据**，把原本需要每天手动翻查多个网站的工作，变成一个**每天自动更新、打开即看**的看板。目标是：

- **少维护**：数据抓取、更新、发布全部自动化，不依赖本地电脑开机；
- **低成本**：全部基于免费/公开数据源 + GitHub 免费托管；
- **可扩展**：模块化设计，新增一个品种或指数，基本只需加配置，不用重写。

目前覆盖五大板块：**电解铝产业链、金属（金/铜/锂）、农产品期货、指数估值、技术指标分析（MACD）**。

## 功能模块

### 1. 电解铝
电解铝产业链的价格、成本、库存等约 11 项指标，按「概览 / 价格 / 成本 / 库存」组织。
- 现货价格、社会库存
- 沪铝主力、氧化铝期货、LME 铝价/库存
- 氧化铝现货、预焙阳极
- 现货升贴水：由现货与主力自算

### 2. 金属（金 / 铜 / 锂）
覆盖紫金矿业等有色股关注的产品价格，概览按金属分块，每个金属可展开历史走势。
- 沪金 / 沪铜 / 碳酸锂期货、上海金现货、COMEX 金、LME 铜价与库存
- 碳酸锂现货（优质电池级 / 电池级 / 工业级）

### 3. 农产品
11 个农产品期货主力连续合约的价格与历史分位，概览网格 + 点击展开走势图（含 20/50/80 分位线）。重点关注分位线低于30%的产品。
- 白糖、棉花、苹果、红枣、花生、棕榈油、玉米、玉米淀粉、豆粕、鸡蛋、生猪：akshare

### 4. 指数估值
沪深300 / 创业板指 / 科创50 的多维估值，帮助判断指数「贵还是便宜」。
- **PE / PB / PS**（加权 + 成分股中位数），及各自的**近5年 / 近10年历史分位**
- **股权溢价指数（ERP）**＝ 1 ÷ PE(TTM) × 100 − 10年期国债收益率（仅沪深300，反映股债性价比）
- 估值分位走势图（主线 + 20/50/80 分位线），支持时间范围联动
- 数据源：中证指数官网（估值）、中债网（10年国债）、理杏仁（PE/PB/PS 及分位）

> 说明：不同指数用最适合它的框架——科创50 盈利波动大，侧重 PB/PS 且不适用 ERP；沪深300 蓝筹为主，保留 ERP。分位口径按各指数**真实可得历史**计算，数据不足不硬凑（如科创50 只有约5年历史，只算近5年分位）。

### 5. 技术指标分析（MACD）
对自选股池（约 190 只，A 股 + 港股）每天做两类 MACD 判断，页面分为 **「MACD」** 与 **「股票池」** 两个子页。

**两类判断**（业务逻辑移植自本地 `stock_alert` 程序，已用 40 组随机行情逐根比对，结果零差异）
- **零轴金叉 / 死叉**：DIFF 上穿（金叉）或下穿（死叉）DEA。日线、周线都算；周线只用**已收完的周**，避免周中未完成的 K 线产生假信号。所有交叉都落库，「零轴附近」（|DIFF| ÷ 收盘价 < 阈值，默认 0.5%）只是**显示层**的筛选，阈值可在页面上直接调。
- **6 态状态机**：按 DIFF、DEA 相对零轴和彼此的位置，给每根 K 线独立判定一个状态，状态变化即「切换事件」，并附触发原因（如低位金叉、DIF上穿零轴、高位死叉）。

| DIFF / DEA 位置 | 状态 |
|---|---|
| 都在零轴下，DIFF < DEA | **弱** |
| 都在零轴下，DIFF ≥ DEA（低位金叉后） | **中性偏强** |
| DIFF > 0 且 DEA < 0 | **极强** |
| 都在零轴上，DIFF ≥ DEA | **强** |
| 都在零轴上，DIFF < DEA（高位死叉后） | **中性偏弱** |
| DIFF < 0 且 DEA > 0 | **极弱** |

> 状态不是单向循环：例如「极强」时 DIFF 跌回零轴下方，会直接变成「中性偏强」。

**MACD 页面**
- 顶部并排两个区域：左边是当日零轴附近的金叉/死叉（标明日线/周线、收盘价、|DIFF|/价），右边是状态切换（旧状态 → 新状态 + 触发事件）。
- 下方是全部股票表：收盘、涨跌幅、当前状态、入此状态日期、已持续交易日、DIFF、DEA、MACD 柱、最近一次交叉、DIF-DEA 差距（占股价 %，越小越接近切换）。可按状态筛选、搜索、排序、只看当日切换。
- 可选任意历史日期查看当天的信号与状态，支持前一日/后一日；A 股休市而港股开市的日子，A 股沿用上一个交易日的状态并用黄色日期标出。
- 红涨绿跌：强状态偏红，弱状态偏绿，与页面其余部分一致。

**股票池页面（在线管理）**
- 单个添加（代码可只写数字，自动判断沪/深/北/港；名称可不填，自动补全）、删除/恢复、重点关注标记。
- **批量导入**：粘贴文本或上传 `.csv / .txt / .yaml`（原 `stock_list.yaml` 可直接导入），先预览再确认；可选「替换整个股票池」。
- 所有修改先暂存，点「保存并更新」才一次性提交；删除只是**停用**，历史数据保留，可随时恢复。
- 保存的原理见下文「技术指标模块的特殊点」。

**数据与口径**
- A 股：Tushare Pro `pro_bar` 前复权日线；港股：腾讯财经前复权日线。MACD 参数 12/26/9。
- 每次拉取近 730 个自然日，前 60 根日线、前 40 根周线只用于 EMA 预热，不落库。
- 前复权基准会随除权变化，所以历史上的 DIFF/DEA 绝对值可能与旧快照有小幅比例差异，但状态判定不受影响。
- 上市时间太短（K 线不足约 65 根）的新股，暂不计算，页面会提示，积累够后自动加入。

## 技术架构

采集与展示解耦，数据流是一条清晰的管线：

```
数据源(接口/网页/API)
      │  采集脚本 *_ingest.py（Python，增量、幂等）
      ▼
   SQLite 数据库（*.db，唯一真相，含完整历史）
      │  导出脚本 *_export.py（读库 → 写 JSON）
      ▼
   静态 JSON（*_api/ 目录）
      │  前端 index.html（原生 JS + ECharts）读取
      ▼
   GitHub Pages 网页
```

**设计原则**
- **采集与展示分离**：抓取只负责写库，前端只负责读 JSON，互不耦合；
- **数据库为唯一真相**：SQLite 存全部历史，导出可随时重算；
- **增量 + 幂等**：每天只补最新数据，重复运行不会产生重复或错误；
- **配置驱动**：指标/品种定义在配置里，前端从 JSON 动态渲染，加指标不改前端；
- **无后端服务**：全部静态托管，零服务器运维。

**技术栈**：Python（采集/导出，除 akshare、tushare + pandas 外基本零依赖）、SQLite、原生 HTML/JS + ECharts（前端）、GitHub Actions（定时任务）、GitHub Pages（托管）。

### 技术指标模块的特殊点
技术指标模块（`tech_*`）沿用同一条管线，但有两点与其他模块不同：

1. **库里存的是每只股票每个交易日的完整指标序列**（`macd_daily`：收盘、DIFF、DEA、MACD 柱、状态、前一状态、触发事件；`macd_cross`：全部金叉/死叉）。因此「查看任意历史日期」不需要额外存快照，直接从库里按日期取即可。导出时按月分片（`tech_api/macd/days/YYYYMM.json`），页面只在选历史日期时才加载对应月份。
2. **前端有一条写回路径，但仍然没有后端服务**：股票池页面通过 GitHub API 把修改提交到 `tech_config/stocks.csv`，这次提交触发 `tech-daily`，工作流再把清单同步进数据库并补算新股。数据库仍是唯一真相，只是「股票池清单」多了一个由页面提交的入口文件。

数据库主要表：`stocks`（股票池，含启用/停用）、`macd_daily`、`macd_cross`、`run_log`（每次运行的成败记录，页面据此提示取数失败或新股数据不足）。

## 自动更新

各模块由独立的 GitHub Actions 定时任务驱动，每天自动「抓取 → 写库 → 导出 → 提交回仓库」，Pages 随之刷新。数据存于仓库、天然带 git 历史备份。

- 商品类（电解铝/金属/农产品）：每日运行
- 指数估值：每日运行，为盘后估值数据留出时间
- 技术指标（`tech-daily`）：每天北京时间 19:30 运行（A 股、港股均已收盘入库）；另外 `tech_config/stocks.csv` 一有提交（例如在页面上改了股票池）就会立即触发一次。同一时间只跑一个，后到的排队，不会互相打断；也可在 Actions 页手动 Run workflow。

## 关于密钥安全

需要鉴权的数据源（如理杏仁）的 token **不写入任何代码文件**，而是存放在 GitHub 仓库的 **Secrets** 中，由 Actions 运行时以环境变量注入。代码里仅通过 `os.environ.get(...)` 读取，公开仓库中不含任何密钥。

**技术指标模块涉及两种密钥，处理方式不同：**
- **`TUSHARE_TOKEN`**（拉 A 股行情）：存放在仓库 **Secrets**，Actions 运行时注入，代码里只读环境变量。
- **GitHub 访问令牌**（页面「股票池」写回用）：由使用者自己创建，**不进入仓库，也不发往 GitHub 以外的任何地方**，只保存在使用者浏览器的 localStorage。请使用 **Fine-grained token**，只选本仓库、只开 **Contents: Read and write**，并设置有效期；不要在公用电脑上保存，随时可在 GitHub 撤销。

## 技术指标模块：使用与维护

**首次部署**
1. 仓库 Settings → Secrets and variables → Actions → 新建 Secret：`TUSHARE_TOKEN`。
2. （可选）Actions → `probe-tech` → Run workflow：验证 Tushare 与腾讯接口在 GitHub 上是否可用。
3. Actions → `tech-daily` → Run workflow：首次需补约两年历史，约 5–8 分钟。完成后仓库里会出现 `data/tech.db` 与 `tech_api/`。

**日常使用**
- 之后全自动，每天 19:30 更新；打开页面「技术指标分析」即可查看。
- 在线改股票池：页面「股票池」→「设置令牌」（只需一次，页面里有逐步说明）→ 增删/导入 → 「保存并更新」。通常 1–2 分钟后刷新页面即可看到新股票的数据（此类提交触发「快速模式」，只计算新增/恢复的股票；每日定时和手动运行仍全量重算，以应对前复权基准变化）。
- 也可以直接编辑 `tech_config/stocks.csv`（列：`code,name,focus`；代码格式如 `600031.SH`、`00700.HK`；`name` 可留空，`focus` 为 1 表示重点关注），提交后同样会自动触发更新。

**本地调试**
```bash
pip install tushare pandas
python3 tech_ingest.py --selftest                 # 离线自检
python3 tech_ingest.py --new-only                # 快速模式：只算股票池里新增/恢复/尚无数据的股票
python3 tech_ingest.py --demo                     # 用合成数据跑通全流程 → data/tech_demo.db（不联网）
python3 tech_export.py --db data/tech_demo.db --out /tmp/tech_api_demo
TUSHARE_TOKEN=xxx python3 tech_ingest.py --only 600031.SH,00700.HK   # 只处理指定代码
```

**可调参数**（`tech_ingest.py` 顶部 / 环境变量）：`TUSHARE_MAX_CALLS_PER_MIN`（默认 45；Tushare 积分更高、额度更大时可调高以加快运行）、`LOOKBACK_DAYS`、`DAILY_WARMUP`、`WEEKLY_WARMUP`。零轴阈值在页面上直接调整，无需改代码。

**常见情况**
- 页面提示「最近一次更新有 N 只股票取数失败」：多为数据源临时故障，下次运行通常自动恢复；失败的股票名称会列在提示里。
- 页面提示「N 只新股上市时间太短」：不是故障，K 线积累够约 65 根后自动加入。
- 在 Actions 里看到 `tech-daily` 因 `stocks.csv` 提交而运行：这是在线改股票池后的正常触发。
